# DaryeelPass

DaryeelPass is a Somali- and English-language clinic discovery and booking-request demo for Hargeisa. It presents clinic-published public information, generated suggested times, and in-app booking requests. It is a portfolio project and is not connected to clinic scheduling systems.

## What works now

- Search clinics by name, service, or publicly listed clinician.
- Create a DaryeelPass account with email and password.
- Request a DaryeelPass suggested time or a time entered by clinic staff. Requests stay inside the app and do not reserve a clinic appointment.
- Track pending requests; invited clinic staff can mark requests confirmed or declined inside DaryeelPass.
- Open clinic websites, call, or email the clinic.
- View the source and date checked for each listing.
- Browse in Somali or English on desktop and mobile.

Suggested times are generated by DaryeelPass and are not clinic availability. Even staff-entered times and in-app confirmations are not connected to clinic scheduling systems and do not reserve or guarantee a visit. The listed clinics have not been onboarded as DaryeelPass partners. Confirm all visit details with the clinic directly. Do not use this app for urgent care; contact emergency services or a clinic directly.

## Run locally

1. Start PostgreSQL using the instructions in [`backend/README.md`](backend/README.md).
2. Install frontend dependencies: `npm install`.
3. In `backend/`, copy `.env.example` to `.env`; set unique `SESSION_SECRET`, `SYSTEM_SETUP_KEY`, and runtime database password values. Install dependencies and run `npm.cmd run db:generate` and `npm.cmd run db:deploy` using the migration-owner `DIRECT_URL`.
4. Run `psql` with `DIRECT_URL` and `-v runtime_password=<same runtime password>` against `prisma/roles.sql` to create the restricted application database role, then use the runtime role in `DATABASE_URL`. Run `npm.cmd run db:seed`.
5. In the repository root, run `npm run dev` to start the API and Vite frontend together, then open `http://localhost:5173`. Press `Ctrl+C` once to stop both. Use `npm run dev:web` if you only need the frontend.

The public clinic directory is read from PostgreSQL through the backend API. The seed includes public clinic details. On first launch, the system setup screen asks for the `SYSTEM_SETUP_KEY` and creates the first system admin; a persistent database marker ensures it never appears again after setup. System admins oversee all clinics and booking requests, invite clinic admins, and can disable or re-enable their accounts. Clinic admins manage their assigned clinic and can invite staff. New patient accounts are not email-verified and password reset email is not configured; this local demo has no automated account recovery.

The account/booking migration removes the old eSignet identity links and synthetic appointment/check-in tables. Back up any local data you need before applying it.

## Data sourcing and maintenance

Clinic names, contact details, service lists, and clinician affiliations in the seed are transcribed from the listed facilities' official sites. Each directory record links to its public source and includes a checked date. Public web listings can become outdated; confirm details directly with the clinic and update the seed when sources change. This project does not independently verify professional registration or clinician availability. DaryeelPass-generated times are illustrative, not sourced from clinics.

## Deployment boundary

This code is a local/portfolio demo, not an operational clinical service. It stores demo account credentials, contact phone numbers, and booking requests in the local database. Use test data only. Staff accounts must be invited by a DaryeelPass admin; in-app staff decisions are not confirmation from a clinic's real scheduling system. Do not enter real patient or identity data.

## Stack

- React and Vite frontend with Somali/English copy and a PWA shell.
- Express API and PostgreSQL database using Prisma.
- PostgreSQL-backed email/password accounts, revocable sessions, and row-level security for account and booking-request data.
